# 从头设计：先询问标签，再依据文献推荐

从头设计、新建表达产物或用户要求改变原标签时读取本文件。此模块定义后续真实项目的询问和检索流程，不在创建技能时向用户询问具体标签，也不预先选一个通用最优标签。

## 标签需求关口

1. 判定当前目标是文献复刻还是新设计。复刻保留作者实际标签、版本、位置和接头；无原始标签信息则继续溯源，不凭习惯补标签。
2. 对每个新设计的目标 CDS 询问：“这个蛋白是否需要添加标签？若需要，主要用于定位/成像、检测/IP、纯化，还是其他目的？”多基因可一轮逐个确认，不能把一个基因的选择套到全部基因。
3. 用户已在当前任务明确选择时沿用，不重复问；记录原指示。用户不添加则保持无标签，不强行检索并推荐。尚未决定就标 pending，可继续文献/概念工作，但不冻结最终序列。
4. 用户需要标签后才启动下面的针对性检索；若用途或平台会改变推荐，集中补问必要信息。用户已指定某标签时仍核验适用文献和序列，若发现冲突给理由与备选，不静默替换。
5. 给出候选和推荐理由，确认最终标签、融合位置及关键接头后再完成序列。将新设计的目标 CDS 登记到 new_expression_target_ids，按 `templates/tag-decision.example.json` 写入 tag_decisions；骨架抗性/维持基因和标签组件不是默认询问对象。

`decision_source=user_explicit` 必须来自用户实际指示，不能由代理替用户填“同意”。`reported_design` 只表示忠实保留原文，不等于用户同意新添加。

## 有针对性的文献检索

先确定物种/组织、目标蛋白及家族、转化与表达方式、实验终点、已有检测/纯化/成像条件，以及已知不可改动的蛋白端部或功能区域。标签、报告基因、定位信号和降解/调控元件分开处理；“需要一个报告读数”不自动等于“将报告蛋白融合到目标上”。

查询以目标蛋白/家族、植物系统和用途逐步组合，优先级为：

1. 同一目标蛋白、同类宿主和相近实验条件的原始研究。
2. 同一蛋白家族或同类植物体系、同一用途的原始研究。
3. 其他体系的间接证据，明确外推差异；方法说明用于补足操作/序列信息，不冒充功能验证。

必须查全文方法、图注、补充材料和原构建，提取实际标签版本、拷贝、位置、连接方式，以及哪项实验支持推荐。区分检测/定位信号、蛋白功能、遗传互补、相互作用/纯化等不同读数，不把一个读数当成所有目标都已验证。

每个关键研究记录标题、作者、期刊/年份、DOI/原始 URL、物种/系统、目标、具体支持实验、结果和限制。记录检索日期、矛盾证据及无法获取的全文；不只依据标题/摘要。

## 推荐矩阵

通常比较 2–4 个与项目相关的候选；证据不足时可以更少，并说明缺口，不为凑数量加入无关标签。标签类别可按荧光读数、表位检测、亲和操作或其他目标检索，但不能预设 GFP、FLAG、某种多拷贝标签或任一品牌普遍最好。

对候选逐项列：

- 精确名称/变体/拷贝和要解决的实验需求。
- 支持的实际目标、宿主和实验；直接/间接证据等级及矛盾。
- N 端、C 端或内部位置的依据，以及接头/连接肽方案；不是只给标签名称。
- 需要检查的定位信号、端部基序、加工/剪切、结构域、功能和互作相关边界；已有证据与待验证风险分开。
- 成像/检测/纯化条件是否与实验室资源兼容，是否需要额外模块/试剂；没有证据时不承诺兼容。
- 与原版或无标签构建的比较、适用的替代位置/标签对照，以及功能判定读数。
- 选择/不选择的理由、证据不覆盖的事项和最小验证计划。

推荐应为“在这些条件与证据下优先测试”，不是保证标签不影响功能。缺少直接证据时明确提出试验候选，允许建议保留无标签功能基线；不要用 Evo2 分数替代功能验证或用户选择。

## 序列落实

从实际文献附件、关联质粒库或可追溯记录取得选定标签的精确 DNA/蛋白版本；编码方案新设计时明确标为新设计，不能以同名标签代替准确版本。保存来源、哈希、完整拷贝/接头和原始文件。

确认 N/C/内部融合、读框、起止密码子、连接肽及需要保留/去除的信号；实际顺序按具体蛋白与证据决定，不硬套“标签一定放最外端”。整体融合 CDS 的 expected_protein 必须含已批准的标签/连接部分，分别注释目标、标签和适用接头。

任何新增连续 ORF 标签融合必须执行 `references/fusion-junctions.md`：从真实来源逐段判断 stop 是否存在和怎样处理，在目标与标签之间加入有明确序列和依据的柔性连接肽，登记 fusion_plan 并验证完整融合产物。C/N 端和内部融合分别处理，不能统一写“去掉目标基因 stop”。

标签的独立 feature ID 放入 tag_feature_ids，必须在目标 CDS 的编码片段内且方向一致。该计算检查仅验证登记一致性；具体位置/边界合理性及标签功能要另外审查。

原版、无标签对照和新标签候选分别版本化。缺少精确序列、最终方案未确认或用户未回答时保留草案，不能让模型或骨架默认标签替用户作决定。

## 报告与边界

在设计报告的“标签决策与文献推荐”中呈现用户决定、候选矩阵、最终方案与来源。把标签未验证的功能/定位/互作影响写入设计边界和待优化验证计划，不当作已发生缺陷，也不写成“标签可检测所以功能无影响”。

本模块没有固定候选排名或实测数据。真实项目需要重新检索与选择，不能把本规则本身当成支持某种标签的文献。
