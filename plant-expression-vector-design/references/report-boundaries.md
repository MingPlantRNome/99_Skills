# 设计报告的边界、缺点、未回答问题与优化计划

生成或修订设计报告时必须读取本文件，使用 `templates/design-report.md` 的相应章节。目标是说明该设计在什么范围内有依据、仍有哪些不足、不能回答什么、何时值得改动；不是为每个设计强行找缺点，也不是添加一段通用免责文字。

## 四项必填内容

### 适用范围与不能保证的结论

限定物种/基因型、组织/时期、转化与表达体系、用途、构建版本和原文条件。逐项区分序列计算通过、实物结构验证和功能验证；不能把一种状态推广到另一种。

对每项主要结论同时说明“支持它的证据”和“证据不支持的外推”。原版精确复刻不等于已在当前条件重现实验结果，骨架适配不等于完整质粒复刻，模型偏好不等于表达增益；是否适用必须由本项目证据解释。

### 已知缺点与设计权衡

每项对应具体对象、证据、影响条件、严重程度理由、当前处理和残余限制。分类必须明确：

- **已证实缺点**：有直接实验、明确版本差异或实际计算失败等支持，注明来源和条件。
- **设计权衡**：为保真、现有材料、可构建性或其他明确目标接受的限制，说明获得什么、牺牲什么。
- **待验证风险**：有理由检查但尚未证明发生的问题，不能写成已经出错。
- **信息缺口**：尚未取得资料或未运行检查，不把它直接等同于生物学缺陷。

未发现已知缺点时注明检查范围和未评估项，不写“没有缺点/风险”。没有直接数据时不编造发生概率、表达损失百分比或置信区间。

### 当前无法回答的问题

每条写具体问题、缺失证据/能力边界、对决策的影响、最少补充资料或验证、可判定终点与交付影响。区分尚未执行、暂时不可获取、模型不覆盖、实验未覆盖和任务不包含，不能用“植物系统复杂”替代原因。

检查下列维度是否与当前项目有关，而不是无条件列为缺陷：

- 各元件/边界/转录本是否确为作者使用版本，未公开改造能否重建。
- 现有宿主和条件是否有足够证据支持原报道功能外推。
- intron/标签/定位或多基因组合的相关读数是否实际验证。
- 新添加标签的推荐证据是否覆盖该蛋白、宿主及融合位置，还是仅支持检测信号；不把标签可检测等同于目标功能不受影响。
- 序列 QC 没有覆盖的 RNA、蛋白和整体功能终点是什么。
- Evo2 是否真实执行，评分是否可比，是否有目标体系的功能校准。

关键序列、身份或结构缺口应同步写入 manifest 的 `unresolved_issues`，阻断对应最终序列交付。未验证功能允许交付明确标注的计算设计，但不得宣称功能已保证；不要把所有未知都不加区分地设为整个项目阻断。

### 待优化方向与验证计划

只提出少量与已发现限制、目标或用户授权相关的方向。每条记录优先级、触发条件、依据/假设、相对原版改动、受保护区域、收益证据等级、代价/风险、原版比较与关键对照、读数及成功/否决判据。

优先级按问题对本次决策的影响确定：

- **P0**：先补阻断性信息或验证，往往是补证，不一定是改序列。
- **P1**：有依据的必要适配和可检验候选比较。
- **P2**：探索性改进，需明确收益尚未证明及何时才值得投入。

保留复刻基线，任何候选不能覆盖原版。对 RNA 保护、蛋白身份和关键接口的约束优先于模型评分；不以 Evo2 单独承诺启动子强度、剪接或表达倍数。无证据支持必要改造时，允许结论为保留原版、先取得功能数据再优化。

成功判据必须对应真实目标；没有可辩护的数值阈值时说明待确定，不编造阈值。重复模型推理不是重复生物学实验，不能用来构造功能置信度。

## 交付前检查清单

1. 四项内容都有项目特异的结论，或有明确的未发现/未评估说明；没有空白和待填写占位。
2. 已证实问题、权衡、风险与缺口没有混写，来源与实际检查记录相符。
3. 无法回答的问题说明原因、决策影响和如何获得答案，不只写“进一步验证”。
4. 阻断项与 manifest、QC、库存状态和实际 Evo2 执行状态一致。
5. 优化方向给出改动、保护约束、对照/读数和可否决条件，未证明的收益写为假设。
6. 报告摘要不超出边界部分的证据；交接同时保留这些限制，不只保留推荐结论。

这些是报告编写与审查规则，不是新的植物实验结果。软件模板检查不能自动证明具体报告中的科学判断正确。
